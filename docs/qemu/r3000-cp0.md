# Q1 R3000 风格 CP0：cpu_mips_r3000_cp0()

本篇说明 QEMU 如何在同一套 MIPS 代码里区分 R3000 风格与 MIPS32 风格的 COP0。硬件行为见[第 12 章 12.2 节](/chapters/12-iop#_12-2-r3000a-核心)，本篇只讲 QEMU 的实现。

文中源码路径均相对于 QEMU 源码树的 `target/mips/`。

## Q1.1 定义

```c
/* target/mips/cpu.h */
/* R3000 CP0: Status has a KU/IE stack instead of EXL and ERL, and RFE */
static inline bool cpu_mips_r3000_cp0(const CPUMIPSState *env)
{
    return !(env->insn_flags & ISA_MIPS2);
}
```

这个函数判断当前 CPU 的 COP0 是不是老式 R3000 风格，判断依据是 CPU 不支持 MIPS II 指令集，也就是 MIPS I 时代的处理器。在本项目中只有 `R3000A` 型号（`insn_flags = CPU_MIPS1`，定义在 `cpu-defs.c.inc`）返回 true，即 PS2 的 IOP；R5900 和其他型号都返回 false。

QEMU 原有的 MIPS 代码只按 R4000/MIPS32 风格处理 COP0，而 R3000 的 COP0 在异常进出、特权级与缓存操作上有本质区别。凡是行为不同的地方，代码都用这个函数分出一条 R3000 分支。

## Q1.2 与 MIPS32 风格的区别

核心区别在 Status（SR）寄存器的低 6 位：

```
R4000 / MIPS32 风格                     R3000 风格
  bit 0    IE   中断使能                  bit 0  IEc ┐ 当前级（current）
  bit 1    EXL  正在处理异常              bit 1  KUc ┘
  bit 2    ERL  正在处理错误              bit 2  IEp ┐ 上一级（previous）
  bit 4:3  KSU  特权模式                  bit 3  KUp ┘
                                          bit 4  IEo ┐ 再上一级（old）
                                          bit 5  KUo ┘
  进入异常：置 EXL = 1                    进入异常：第 5:0 位左移 2 位（压栈），当前级清零
  返回：ERET                              返回：RFE，第 5:2 位右移到第 3:0 位（出栈）
```

R3000 没有 EXL、ERL 位，用三级 KU/IE 栈记录异常嵌套。KU = 1 表示用户态，KU = 0 表示内核态。

## Q1.3 调用点

| 文件与函数 | R3000 分支的行为 |
|---|---|
| `tcg/system/tlb_helper.c` `mips_cpu_do_interrupt()` → `r3000_enter_exception()` | **进入异常**：写 EPC 与 Cause.BD，`Status = (Status & ~0x3f) \| ((Status << 2) & 0x3c)` 压栈，当前级变为内核态、关中断；BEV = 1 时跳到 `0xBFC00180`，否则跳到 `0x80000080`（MIPS32 为 `0x80000180`）；写 Cause.ExcCode |
| `tcg/system/special_helper.c` `helper_rfe()` | **异常返回**：`Status = (Status & ~0xf) \| ((Status >> 2) & 0xf)` 出栈，KUo、IEo 保持不变。它不调用本函数，但与上一行配套 |
| `internal.h` `cpu_mips_hw_interrupts_enabled()` | **中断是否开启**：R3000 只看 IEc；MIPS32 还要检查 EXL、ERL、调试模式等 |
| `internal.h` `compute_hflags()` | **当前特权级**：R3000 由 KUc 决定是否为用户态（`MIPS_HFLAG_UM`）；MIPS32 看 KSU、EXL、ERL。结果存入 `hflags`，翻译指令时据此判断特权指令能否执行 |
| `cpu.c` `mips_cpu_reset_hold()` | **复位值**：R3000 只置 BEV；MIPS32 同时置 BEV 与 ERL（R3000 没有 ERL）。用户态模拟（`CONFIG_USER_ONLY`）下 R3000 置 KUc，MIPS32 设置 KSU |
| `system/cp0.c` `cpu_mips_store_cause()` | 写 Cause 时，R3000 只允许软件改 IP0、IP1 两个软件中断位 |
| `system/cp0.c` `cpu_mips_store_status()` | 64 位段权限变化时的刷新只对非 R3000 进行；R3000 的 IsC 位变化时刷新 QEMU 的 softmmu TLB（见 Q1.4） |
| `tcg/system/tlb_helper.c` `r3000_store_isolated()` | 判断一次写操作是否处于缓存隔离状态（见 Q1.4） |
| `system/machine.c` `mips_r3000_needed()` | 迁移与快照时，只有 R3000 才保存 `cpu/r3000` 子段，即断点寄存器 BPC、BDA、DCIC、BDAM、BPCM |

## Q1.4 缓存隔离的实现

R3000 没有 CACHE 指令。软件把 SR.IsC（第 16 位）置 1 后，存储操作只进入数据缓存而不到达存储器，IOP 内核借此清除缓存（硬件说明见 [12.2.3 节](/chapters/12-iop#_12-2-3-缓存隔离)）。

QEMU 不模拟缓存，用第二个地址空间代替：

1. **建立隔离地址空间**：`cpu.c` 的 `mips_cpu_realizefn()` 对不支持 MIPS II 的 CPU 额外建立地址空间 `cpu-isolated`（索引 `MIPS_ASIDX_ISOLATED`）。它的后端是 `r3000_isolated_ops`：`r3000_isolated_read()` 返回 0，`r3000_isolated_write()` 丢弃写入。`mips_cpu_cpudef_class_init()` 同时把这类 CPU 的 `max_as` 设为 `MIPS_ASIDX_ISOLATED`。
2. **只把写操作导向隔离空间**：`mips_cpu_tlb_fill()` 填 softmmu TLB 时调用 `r3000_store_isolated()`。该函数在 IsC = 1 且目标物理地址是 RAM 或 ROM 时返回 true。此时：
   - 如果本次访问是存储，页表项带上 `MemTxAttrs.secure = 1`，权限只有写；
   - 如果本次访问是读取，页表项去掉写权限，读仍从普通地址空间进行，之后的写会因为没有写权限而重新填表。

   `mips_cpu_asidx_from_attrs()` 把 `secure = 1` 映射到 `MIPS_ASIDX_ISOLATED`，于是写入落到隔离空间被丢弃。外设寄存器不是 RAM/ROM，写入照常生效。由于读不会经过隔离空间，`r3000_isolated_read()` 在正常运行中不会被调用。
3. **IsC 切换时刷新**：softmmu TLB 中的页表项依赖 IsC 的状态（是否带 `secure`、是否有写权限）。所以 `cpu_mips_store_status()` 在 IsC 变化时调用 `tlb_flush()`，让之后的访问按新状态重新填表。

## Q1.5 小结

`cpu_mips_r3000_cp0()` 是"这颗 CPU 是否使用 PS2 IOP 那样的 MIPS I 式 COP0"的开关。它为 true 时，异常进出（KU/IE 栈与 RFE）、中断与特权级判断、复位值、Cause 可写位以及缓存隔离都改用 R3000 的规则。
